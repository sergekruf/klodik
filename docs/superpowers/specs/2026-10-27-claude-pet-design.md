# Клодик — питомец для Claude Code (дизайн MVP)

Дата: 2026-10-27. Статус: черновик на утверждение.

## Зачем

Пользователь параллельно ведёт много сессий Claude Code в десктопном приложении Claude: за последние 2 дня их было 85, 248 из 249 за две недели запущены во вкладке Code. Сессии заканчивают работу или ждут ответа, пока пользователь сидит в другом окне. Из-за этого они простаивают или забываются.

Клодик — маленький пиксельный персонаж поверх всех окон в образе оранжевого талисмана Claude Code с чёрными глазами. Он знает обо всех сессиях, которым нужен пользователь, и аккуратно напоминает о них, пока все не будут закрыты. Когда закрывать нечего, он спокойно лежит и не отвлекает.

Пример из Codex: там у приложения есть встроенные питомцы (Codex Pets), которые показывают статус задач и напоминают о них. У Claude такого нет, поэтому делаем отдельное приложение.

## Цели

1. Видеть краем глаза, что есть сессии, которые ждут пользователя, и сколько их.
2. Напоминать, пока такие сессии не закрыты, и переставать, как только всё закрыто.
3. Компактный список таких сессий. Клик по строке открывает сессию в Claude.
4. Почти нулевая нагрузка на систему и никакого замедления Claude.

## Не цели

- Не писать в сессию из питомца: никаких ответов, разрешений или кнопок «allow/deny».
- Не поддерживать сессии в терминале и VS Code. Только десктопное приложение Claude.
- Только macOS, без Windows и Linux.
- Без публикации, подписи для App Store и автообновлений. Сборка для себя.

## Анти-цели (провал, даже если всё работает)

- Клодик прыгает без причины или не успокаивается, когда всё закрыто. Тогда его выключат.
- Ощутимо тормозит Claude или жрёт батарею.
- Ломает настройки Claude Code (`~/.claude/settings.json`) или существующие хуки пользователя.

## Состояния сессии

| Метка | Цвет точки | Когда ставится | Когда снимается |
|---|---|---|---|
| Нужен ответ | серая | Claude просит разрешения или задал вопрос: хук `PermissionRequest`, хук `Notification` с `permission_prompt`, `elicitation_dialog`, `agent_needs_input`; или итог хода в файле сессии `postTurnSummary.status_category == "blocked"` | Пользователь ответил: хук `UserPromptSubmit` этой сессии, следующий `PostToolUse` после разрешения, или новый ход, у которого итог уже не `blocked` |
| Закончила, не прочитана | синяя | Claude закончил ход позже, чем пользователь последний раз открывал сессию: `lastTurnEdgeAt > lastFocusedAt` и итог не `blocked` | Пользователь открыл сессию в Claude, то есть `lastFocusedAt` стал позже `lastTurnEdgeAt` |
| Напомнить | синяя с отметкой | Пользователь сам поставил её правым кликом по строке в списке питомца | Пользователь открыл сессию после того, как поставил метку, или снял её правым кликом |
| Работает | — | Хук `UserPromptSubmit` или `PreToolUse` | Хук `Stop` / `StopFailure` / `SessionEnd` |

**Серая сессия, которую уже открывали (решение пользователя).** Если пользователь открыл серую сессию (`lastFocusedAt` позже момента, когда она начала ждать ответа) и не ответил, она остаётся в списке и в бейдже, но Клодик из-за неё не прыгает. Прыгает он только из-за серых сессий, которые ещё не открывали. Момент начала ожидания — `lastTurnEdgeAt` для итога `blocked` из файла или время события хука. Отсюда и первый запуск: старые серые сессии, которые уже открывали, просто тихо стоят в списке.

«Работает» в список не попадает. Оно нужно только для анимации: Клодик что-то печатает.

**Решение строителя (моё):** в список попадают только неархивные сессии с активностью за последние 7 дней. Иначе старые брошенные сессии с итогом `blocked` (сейчас их 41) не дадут Клодику успокоиться никогда. Правый клик даёт «Скрыть до следующей активности»: строка исчезает, пока в сессии не случится новый ход.

## Поведение Клодика

- **Спокойствие.** Список пуст: Клодик дышит, моргает. Если долго ничего не происходит, засыпает (Zzz).
- **Работа.** Хотя бы одна сессия работает и нет серых или синих: печатает или что-то мастерит.
- **Синие есть, серых нет.** Над головой бейдж с числом. Раз в несколько минут коротко машет.
- **Серые есть, но все уже открывались или ждут дольше суток (решение пользователя).** Ведёт себя как при синих: бейдж и изредка машет.
- **Есть серые, которые ещё не открывали.** Подпрыгивает и машет. Чем дольше самая старая из них ждёт, тем чаще и заметнее: до 2 минут — раз в минуту, 2–10 минут — раз в 30 секунд, больше 10 минут — непрерывно подпрыгивает. Это моя раскладка, её можно править в настройках.
- **Новое событие.** Сессия только что закончила или запросила ответ: показывается пузырь с её названием на пару секунд, Клодик радуется или машет.
- **Claude на переднем плане.** Не прыгает, только бейдж. Пузыри не показывает.
- **Отложить.** Правый клик по Клодику: «Отложить на 30 минут». Всё это время только бейдж.
- **Перетаскивание.** Клодика можно перетащить в любое место экрана, позиция запоминается. По умолчанию — правый нижний угол над Dock.

## Список сессий

Открывается кликом по Клодику, закрывается кликом вне списка или Esc. Компактная всплывашка рядом с Клодиком.

- Строка: точка (серая / синяя / синяя с отметкой), название сессии, имя папки проекта, сколько ждёт («12 мин»).
- Сортировка: сначала серые, потом синие, внутри — самые старые сверху.
- Клик по строке открывает сессию в Claude: `open "claude://code/continue?session=<cliSessionId>"`. Проверено вручную: ссылка открывает нужную сессию и не создаёт новую.
- Правый клик по строке: «Напомнить» / «Не напоминать», «Скрыть до следующей активности».
- Внизу: «Отложить на 30 минут», «Настройки», «Выйти».

## Как устроено

### Части

1. **Приложение Клодика.** Нативное Swift-приложение для macOS (AppKit + SwiftUI для списка), без иконки в Dock (`LSUIElement`). Прозрачное окно без рамки поверх всех окон и на всех рабочих столах (`NSPanel`, `.floating`, `canJoinAllSpaces`).
2. **Хуки Claude Code.** Они сразу сообщают Клодику о событиях. В `~/.claude/settings.json` дописываются хуки `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Notification`, `Stop`, `StopFailure`, `SessionEnd`.
3. **Наблюдение за файлами сессий приложения.** Это источник правды для названий, «прочитано / не прочитано» и итога хода.

### Хуки

- Предпочтительно HTTP-хуки (`"type": "http"`) на `http://127.0.0.1:<порт>/event`. Они не запускают процесс, поэтому нагрузка около нуля.
- Строитель обязан проверить: если Клодик не запущен, HTTP-хук не должен ни тормозить, ни ломать сессию, ни сыпать ошибками пользователю. Если это не так, использовать запасной вариант: command-хук с `"async": true` и `curl -s -m 1 ... || true`.
- В каждом событии есть `session_id`. Это `cliSessionId` в файлах приложения и параметр ссылки `claude://code/continue`.
- Установка хуков делается командой из меню Клодика или скриптом. Существующие хуки пользователя сохраняются (сейчас там есть `SessionStart` → `~/scripts/hub-context.sh`), перед записью делается копия `settings.json`. Есть команда удаления хуков. Хуки Клодика помечаются так, чтобы их можно было найти и убрать.

### Файлы сессий приложения

- Путь: `~/Library/Application Support/Claude/claude-code-sessions/<id>/<id>/local_<uuid>.json`, по файлу на сессию. Одна сессия может лежать копиями в папках разных аккаунтов (сейчас 586 файлов на 389 сессий), побеждает копия с самым поздним `lastActivityAt`. Это внутренний формат приложения Claude, он может поменяться при обновлении.
- Нужные поля: `sessionId` (`local_…`), `cliSessionId`, `title`, `cwd`, `isArchived`, `lastFocusedAt`, `lastTurnEdgeAt`, `lastActivityAt`, `postTurnSummary.status_category` (`completed` / `blocked` / `review_ready`), `postTurnSummary.status_detail`.
- Следить через FSEvents. Перечитывать только изменившиеся файлы, при старте читать всё один раз.
- Приложение пишет файл не мгновенно: по наблюдению, на границе хода и с задержкой до минуты. Строитель должен замерить, как быстро обновляется `lastFocusedAt`, когда сессию просто открыли. Неизвестно и то, обновляется ли `lastFocusedAt`, если сессия закончила ход, пока она открыта на экране. Если не обновляется, Клодик будет показывать синюю точку у сессии, которую пользователь и так видит. Тогда считать сессию прочитанной, если Claude на переднем плане и в его окне открыта эта сессия, либо принять это ограничение.
- Если формат файлов сломался (нет нужных полей), Клодик работает только по хукам и показывает в меню предупреждение. Падать нельзя.
- Ручная метка «непрочитано» самого приложения Claude на диск не пишется, поэтому её заменяет своя метка «Напомнить».

### Хранение своего состояния

`~/Library/Application Support/Klodik/state.json`: позиция, метки «напомнить», скрытые сессии, настройки. Без базы данных.

### Внешний вид

- Пиксельный оранжевый талисман с чёрными глазами, примерно 48×48 точек на экране, крупные чёткие пиксели без сглаживания.
- **Решение строителя:** спрайты рисуются кодом из пиксельной сетки или вручную в PNG. Генерация картинок не обязательна.
- Анимации: дышит / моргает, печатает, машет, прыгает, радуется, спит. 6–8 кадров каждая, 8–12 кадров в секунду.
- Это личный инструмент. Талисман Claude — товарный знак Anthropic, публично как «официальный» не распространять.

## Ограничения по нагрузке

- В покое ниже 0,5% CPU. Анимация «дышит / моргает» реже: таймер, а не постоянная отрисовка. Когда Клодик спит, кадры не рисуются вообще.
- Память — до 40 МБ.
- Ни одного опроса чаще раза в секунду. Только события: FSEvents, HTTP, уведомление о смене активного приложения (`NSWorkspace`).
- Хуки не добавляют Claude ощутимой задержки.

## Решения строителя по итогам проверки

- **Запрос разрешения.** Серая точка ставится сразу по хуку `PermissionRequest`. `Notification` с `permission_prompt` приходит на ~6 с позже и служит запасным сигналом. Снимается по `PostToolUse` той же сессии. HTTP-ответ Клодика на `PermissionRequest` — пустой `200`, никакого решения за пользователя. Строитель проверяет, что пустой ответ не влияет на запрос.
- **Сессия на экране.** Разрешение Accessibility не запрашиваем. Сессия, открытая сейчас в Claude, — это сессия с самым свежим `lastFocusedAt` среди всех файлов (так видно по замеру). Если Claude на переднем плане, когда эта сессия заканчивает ход, она считается прочитанной и синей точки не получает.

## Результаты разведки (2026-10-27)

- **HTTP-хук на выключенный порт** не мешает сессии: ошибок не видно, задержка меньше 0,1 с. На включённый порт события доходят, в теле есть `session_id`, `cwd`, `hook_event_name`. Используем HTTP-хуки, запасной вариант не нужен.
- **Хуки во вкладке Code** срабатывают все: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PermissionRequest`, `Notification`, `Stop`. `session_id` совпадает с `cliSessionId` в файле сессии.
- **Запрос разрешения:** `PermissionRequest` — сразу, `Notification` (`permission_prompt`, «Claude needs your permission to use Bash») — через ~6 с. Команды, которые только читают (например, `date`), Claude Code разрешает сам, без запроса.
- **`lastFocusedAt`** меняется при каждом переключении на сессию, файл записывается через 1–2 с. Во время ожидания разрешения `lastTurnEdgeAt` тоже сдвигается, а `postTurnSummary` пишется только в конце хода.

## Настройки (минимум)

Окно в 2 вкладки или просто пункты меню: запуск при входе в систему (`SMAppService`), окно в днях (7), шкала напоминаний, установить / удалить хуки, порт.

## Что оставлено строителю

Структура проекта (Xcode-проект или Swift Package), выбор порта, формат событий между хуками и приложением, точная анимация и кадры, вёрстка списка, логирование.

## Проверено при подготовке

- Ссылка `claude://code/continue?session=<cliSessionId>` открывает существующую сессию.
- В файлах сессий есть `lastFocusedAt`, `lastTurnEdgeAt`, `postTurnSummary.status_category`.
- Ручная метка «непрочитано» на диск не пишется: поставлена через боковую панель, в файлах изменений нет.
- Хуки Claude Code работают во вкладке Code: `SessionStart`-хуки пользователя срабатывают в десктопных сессиях.
- Окружение: macOS 27.2, Xcode установлен, Swift 6.4.
